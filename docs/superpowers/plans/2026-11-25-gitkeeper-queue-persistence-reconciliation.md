# Queue Persistence and Reconciliation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. A fresh implementer and a fresh reviewer are required for every code slice.

**Goal:** Implement the local queue/persistence and GitHub reconciliation portions of the approved pilot without enabling worker execution.

**Architecture:** A standard-library Python domain layer records repair cycles, queue projections, leases, attempts, and operational telemetry in SQLite outside both repositories. A GitHub port reads authoritative PR/check/config facts and projects at most one worker label; a queue service applies the readiness policy before any atomic local claim. A restart reconciler and single-flight adaptive poller recover from missed events and outages without webhooks or inbound listeners.

**Tech Stack:** Python 3.10+, standard-library `sqlite3`, `urllib`, `dataclasses`, and `unittest`/`pytest`; no new runtime dependency.

## Global Constraints

- The automatic worker remains disabled. This plan adds no worktree creation, OpenCode launch, patch publication, model fallback, QML/UI integration, settings or workflow changes, or Setu-mobile changes.
- GitHub is authoritative for remote PR state, current head SHA, check results, merged/default-branch config, and labels. Local SQLite is the execution/recovery record; labels are projections, never locks.
- SQLite files live outside every watched repository and the GitKeeper repository. Construction must reject a state path equal to or beneath either resolved root, including through symlinks/junctions.
- The logical work identity is `(repository, pr_number, head_sha, cycle_id)`. A lease also carries an unguessable `lease_id` and monotonically increasing generation; each claim has an unguessable `attempt_id`. Only one active local lease may exist in the single-worker pilot. Claims are atomic and duplicate-safe across connections/processes. Renewal, cancellation, start, and completion require the exact expected cycle/lease/attempt identity; an owner name or same-SHA match alone is never authority.
- A new head SHA cancels stale work. Closing a PR cancels it. Reopening starts a fresh repair cycle and automatic budget while preserving history. Stale completions cannot publish or overwrite current labels.
- At most **3 automatic invocations per open/reopen cycle**, across head-SHA changes. Explicit owner retries are separate records and never replenish that budget. The unique `reserved -> running` commit immediately before process creation is the counted launch record; a crash after that commit is conservatively counted even if spawning did not finish. `reserved` and `model_unavailable` attempts are excluded; `recovered_unknown` reached from `running` is included. An explicit retry authorizes exactly one claim and at most one launch, not an unbudgeted queue loop.
- The only remote queue labels are `gitkeeper/worker-queued`, `gitkeeper/worker-running`, and `gitkeeper/worker-blocked`; a successful projection has at most one. Preexisting/partial conflicts are observed, deleted before repair, and verified away; they never confer eligibility.
- Automatic eligibility requires exact `SumukhaK` authorship, a same-repository head, repository allowlist and privacy verification, an open non-draft PR, merged/default-branch config, a valid current-SHA repair reason, and available budget.
- Current-SHA required checks all passing mean ready/no worker. A repair reason exists only for an explicit deterministic check failure or explicitly submitted Claude feedback. Missing, stale, cancelled, skipped, timed-out, action-required, neutral, or unknown required-check outcomes block; infrastructure and unknown outcomes are never code failures.
- Only `pull_request` secret-free/read-only CI and label-only jobs that never check out or execute PR code may exist. The control plane does not add workflows, change permissions, or read secrets into QML, SQLite, telemetry, labels, or worker subprocesses.
- Offline GitHub means no new claims or authoritative transitions. Preserve local state, show a stale/offline condition, and retry with capped backoff. A failed label write preserves the lease/run record and never displays false remote success.
- Polling is outbound and adaptive. There are no inbound listeners. Use the implementation rulings below for concrete timing. Waits use a stop event or bounded chunks that recheck stop, never an uninterruptible full-delay sleep.
- Reconciliation returns both changed local items and a typed per-repository health report. A repository-list failure is not an empty successful list, and one PR/check/config failure is not a successful repository pass.
- Telemetry retention defaults to 90 days and can only be shortened. It stores timestamps/durations, PR/revision identifiers, transitions, attempts, outcomes, selected model ID, and categorized errors only. Never store source, diffs, prompts, credentials, screenshots, raw commands/scripts, environment values, or full OpenCode input/output.
- Claude feedback is restricted work input, not telemetry. Its UI submission and worker handoff belong to Task 3 of the source plan, not this plan.
- Corrupt or unavailable SQLite prevents claim/continuation and must not replace, delete, or rewrite existing database/sidecar files.
- Every commit includes `Co-authored-by: Copilot App <223556219+Copilot@users.noreply.github.com>`. Every task gets its own PR, fresh independent review, merged PR evidence, and tracker/README update before the next task starts.
- The README must continue saying plainly that worker execution is disabled. GitHub About changes only if project scope/description changes; this plan does not change either.

## Recorded Implementation Rulings

1. **Repair-reason wire values:** the new queue/UI domain owns `deterministic_check_failure`, `claude_feedback`, and `manual_retry`. Task 1 adds an explicit adapter to the existing readiness values `deterministic-check-failure` and `review-feedback`; it does not silently rename either existing API and creates no import cycle.
2. **Adaptive defaults:** active work polls every 15 seconds; idle every 60 seconds; a remote failure starts at 30 seconds and doubles to a 300-second cap. The poller adds no random jitter in this pilot, so timing is deterministic in tests. These are local defaults and do not widen the merged remote schema, whose `polling_preferences` remains exactly `{"mode": "adaptive"}`.
3. **Automatic invocation accounting:** the future runner is source-plan **Task 4**, not Task 3. Task 1–5 define the launch/outcome lifecycle and atomic budget port; they do not launch OpenCode. A claim reserves no automatic invocation or model. Immediately before subprocess start, source-plan Task 4 must recheck remote eligibility and the per-cycle budget, atomically move the claim's unique attempt `reserved -> running`, and persist it before process creation. Later completion is idempotent by `attempt_id`. `model_unavailable` outcomes are terminal but exempt from the three-automatic-invocation count. A crash can recover through the reserved/recovery protocol below; it cannot silently create a second launch authorization.
4. **Database layout:** queue/history/pause state and telemetry use separate SQLite files in the same external state directory. A schema-version mismatch raises `StorageUnavailable`; this plan does not implement migrations or destroy an unknown schema.
5. **PR discovery:** one outbound poll lists open PRs for each configured repository. Local observations not present in a complete open-PR listing are treated as closed; any repository-list failure blocks all authoritative transitions for that repository and cancels none of them speculatively.
6. **Time:** domain timestamps are timezone-aware UTC; SQLite stores UTC ISO-8601 strings. Durations are non-negative integer milliseconds. Tests inject a clock rather than sleeping.
7. **Label reconciliation:** every projection first performs an explicit remote label read. If conflicting GitKeeper labels exist, delete those conflicts before adding the desired one; then read labels again and verify exact convergence before recording remote success. Desired-state writes are idempotent but are not a distributed transaction. After a partial failure, the next poll reads actual remote labels and retries. The local item is marked stale/offline instead of claiming remote success.
8. **UI service compatibility:** one `QueueService` instance is bound to one repository, matching the existing PR-number-only UI/fake methods and avoiding cross-repository ambiguity. The reconciler maps repositories to their service instances; `get_queue_status()` remains a boolean. Task 1 owns a small immutable `QueueViewAdapter` and `TelemetryViewAdapter`; Task 5 service methods return domain items, while the future UI-integration slice wraps them without editing QML. Domain `updated_at` maps to status `last_updated`, and telemetry `invocation_count` maps to `attempt_count`.
9. **Default-branch immutability:** resolve the repository's default branch and its commit SHA first, then fetch `.github/gitkeeper.json` by that immutable commit ref. A later branch advance cannot change the requested content; the next poll resolves the new SHA. The Contents API's returned blob SHA is not a commit SHA and is never compared to `default_branch_sha`. Missing/malformed content fails closed; no moving-ref fallback is allowed.
10. **Retry authorization:** an owner retry creates a high-entropy, single-use authorization bound to repository/PR/head/cycle and an expiry. Only `claim(..., retry_authorization=...)` may consume it, atomically with the lease/claim. Remote facts and eligibility are revalidated before consumption. SHA change, close/reopen, or expiry permanently invalidates it. Pause, ineligibility, or an existing active claim refuses that claim without consuming the authorization; a still-unexpired token may be used after the temporary condition clears. Replay never creates another launch.
11. **Telemetry scheduling:** the Task 7 poller owns automatic expiry and runs it before each poll and once at startup, including after a restart or shortened retention. Task 3 provides and tests `TelemetryStore.expire`; no UI refresh or repository network success is required to trigger deletion.

## Review Focus

1. **Unusual/missing check outcomes:** a missing required check, duplicate check name, stale SHA, or GitHub infrastructure conclusion must block rather than queue deterministic repair — pinned in Task 1 and Task 5.
2. **Concurrent processes and restarts:** two workers claiming the same revision, an expired lease, or a restart with an active lease must never launch duplicates; interrupted leases become reclaimable only after expiry — pinned in Task 2.
3. **Adversarial fork/config/label input:** a fork author, remotely supplied policy key, stale config, or preexisting worker label must not bypass the local gate — pinned in Tasks 1, 4, and 5.
4. **Remote failure between local and remote writes:** a partial label update, offline poll, or new SHA between claim and completion must preserve records and prevent false/stale remote success — pinned in Tasks 4, 5, and 6.
5. **Sensitive data and destructive storage handling:** telemetry rejects non-operational payloads, credentials never enter persisted errors, and corrupt/unknown-version databases are preserved — pinned in Tasks 2, 3, and 4.

## Exact Domain Contract

Task 1 must implement this schema with frozen dataclasses and string-valued enums. `MappingProxyType` makes nested configuration mappings read-only. Every timestamp is timezone-aware UTC; identifiers/SHAs/model IDs are trimmed, non-empty strings; counts/durations/PR numbers are exact `int` values (`bool` is rejected). SHAs are exactly 40 lowercase or 64 lowercase hexadecimal characters. Model IDs start with `opencode/`, have a non-empty suffix, and contain no whitespace. Repository names match `owner/repository`, with non-empty GitHub-safe components. Locally generated cycle, request, lease, attempt, event, and authorization IDs are unguessable lowercase UUID4 strings (36 characters); GitHub check-run IDs are trimmed positive decimal strings. Never derive lease, attempt, or retry authority from a PR number, SHA, counter, owner, or clock.

- **`PilotConfig`**: `worker_enabled: bool`, `polling_preferences: Mapping[str, str]`, `motion_preference: str | None`, `deterministic_check_ids: tuple[str, ...]`, `default_branch: str`, `default_branch_sha: str`. `polling_preferences` is exactly `{"mode": "adaptive"}`; motion is `None`, `"reduced"`, or `"disabled"`; the check-ID tuple is non-empty, with unique, trimmed, non-empty string IDs ordered as published. All four wire keys are required, and no others are accepted: `worker_enabled`, `polling_preferences`, `motion_preference`, and `deterministic_check_ids`. Default-branch metadata comes only from trusted repository reads, never payload keys. Config is immutable; `default_branch_sha` is the immutable commit ref used for the content request, not the Contents API's blob SHA.
- **`CheckConclusion`**: `success`, `failure`, `neutral`, `cancelled`, `skipped`, `timed_out`, `action_required`, `stale`, `startup_failure`. **`CheckOutcome`**: `passed`, `deterministic_failure`, `blocked`, `unknown`. Only `success` and `failure` are eligible for deterministic classification. Task 4 maps a current-head workflow/job/suite infrastructure failure to `startup_failure`; a stale successful run with the same name cannot override it.
- **`CheckResult`**: `check_id: str`, `check_run_id: str`, `head_sha: str`, `conclusion: CheckConclusion`. The decimal run ID is unique among results; `check_id` is required. `head_sha` is the run's actual SHA, which may be stale relative to its `CheckState`; Task 4 maps that mismatch to `CheckConclusion.stale`, never success.
- **`CheckState`**: `head_sha: str`, `required_check_ids: tuple[str, ...]`, `results: tuple[CheckResult, ...]`. The required-ID tuple is non-empty, each required ID is unique/non-empty, every result has a required ID, and stale-SHA evidence may remain in `results`. `outcome` precedence is: `blocked` for any result whose SHA differs from the state or any non-success/failure conclusion; otherwise `unknown` unless every required ID has exactly one result; otherwise `deterministic_failure` when all required results are success/failure and at least one is failure; otherwise `passed` only when every required result is success. Expose `checks: CheckState` on queue/status values so existing `checks.outcome.value` and `check_state.outcome.value` consumers work.
- **`PullRequestSnapshot`**: `repository`, `pr_number`, `author: str | None`, `head_repository: str | None`, `head_sha`, `is_open`, `is_draft`, `observed_at`. Scalar PR facts come from one authoritative response; `observed_at` is the local UTC observation clock. `pr_number >= 1`; deleted author/head-repository values remain `None` and fail the relevant safety gate. Same-repository means exact `head_repository == repository`; author matching is exact case-sensitive equality with `OWNER_LOGIN`.
- **`RepairReason`**: `deterministic_check_failure`, `claude_feedback`, `manual_retry`. **`WorkerState`**: `ready`, `queued`, `running`, `blocked`. **`WorkerLabel`**: `gitkeeper/worker-queued`, `gitkeeper/worker-running`, `gitkeeper/worker-blocked`. Desired state/label pairs are ready/None, queued/queued, running/running, blocked/blocked; paused is a separate global preference, not a worker state. **`Blocker`** is the existing `gitkeeper.host_mode.readiness.Blocker` imported unchanged, and **`ReadinessBlocker`** is its existing frozen `(code: Blocker, detail: non-blank str)` value; queue classification may emit `REPOSITORY_NOT_ALLOWLISTED`, `REPOSITORY_PRIVACY_UNVERIFIED`, `FORK_HEAD`, `AUTHOR_NOT_OWNER`, `PR_CLOSED`, `PR_DRAFT`, `CONFIG_NOT_MERGED`, `WORKER_DISABLED`, `NO_REPAIR_REASON`, `STALE_CHECK_SHA`, and `ATTEMPT_BUDGET_EXHAUSTED`, but not host/CLI/model/broker blockers.
- **`ErrorCategory`**: `storage_unavailable`, `storage_corrupt`, `schema_mismatch`, `github_unavailable`, `github_authorization`, `github_response`, `remote_stale`, `local_lease_conflict`, `stale_head`, `retry_invalid`, `retry_expired`, `retry_replayed`, `attempt_budget_exhausted`, `model_unavailable`, `worker_unavailable`, `worker_failed`. **`OperationalError`**: `category: ErrorCategory`, `message: str`, `occurred_at: datetime`; it is persisted data, not an exception. Message is a short fixed local category description; reject exception objects, response bodies, and arbitrary mappings. Task 1's typed exceptions carry only these categories through adapters.
- **`QueueKey`**: `repository`, `pr_number`, `head_sha`, validated as above. **`RepairCycle`**: `cycle_id` (UUID4), `cycle_number: int >= 1`, `initial_key: QueueKey`, `opened_at`, `closed_at: datetime | None`. Exactly one open cycle exists per repository/PR, cycle numbers increase monotonically, `closed_at` is absent for an open cycle and otherwise `>= opened_at`, and a head-SHA change updates the queue key/observation but does not change the open cycle. **`RepairRequest`**: `request_id` (UUID4), `key`, `cycle_id`, `reason`, `owner: str | None`, `requested_at`, `expires_at: datetime | None`, `consumed_at: datetime | None`, `retry_authorization: str | None`. Automatic requests allow deterministic failure/Claude feedback and have no owner, expiry, authorization, or consumption; manual requests use reason `manual_retry`, exact `OWNER_LOGIN`, a UUID4 authorization, an expiry strictly later than `requested_at`, and at most one `consumed_at >= requested_at` that must precede expiry.
- **`ClaimResult`**: `lease: Lease`, `attempt: InvocationAttempt`, `authorization: RetryAuthorization | None`; the attempt is initially `reserved`. Manual claims carry the consumed authorization; automatic claims leave it absent. A replay never returns the prior lease/attempt: an active claim or duplicate start raises the exact Task 2 conflict error, and retry-token replay raises `RetryReplayed`.
- **`RetryAuthorization`**: `authorization` (UUID4), `request_id`, `key`, `cycle_id`, `owner`, `kind: InvocationKind = manual_retry`, `created_at`, `expires_at`, `consumed_at: datetime | None`. Its originating request must satisfy `request.request_id == request_id`, `request.retry_authorization == authorization`, and equal key/cycle/owner/reason/expiry; owner is exact `OWNER_LOGIN` and kind is `manual_retry`. UUID4 provides 122 random bits, not merely length. Expiry is strictly later than creation; consumption is absent or satisfies `created_at <= consumed_at < expires_at`; only `claim` may consume the record atomically once. Repository/PR/head/cycle mismatch permanently prevents use; pause/active-claim/eligibility refusal consumes nothing and preserves audit history.
- **`Lease`**: `lease_id`, `generation: int >= 1`, `attempt_id`, `owner`, `key`, `cycle_id`, `claimed_at`, `expires_at`, `cancelled_at: datetime | None`. `expires_at > claimed_at`; cancellation is absent or `cancelled_at >= claimed_at`. `owner` is the fixed metadata string `gitkeeper-automatic` for automatic claims and exact `OWNER_LOGIN` for manual claims, never an authentication or fencing identity. A lease grants a claim, not proof of a running subprocess; generation increases only for a replacement lease on the same logical key. **`InvocationKind`**: `automatic`, `manual_retry`. **`AttemptOutcome`**: `reserved`, `running`, `completed`, `model_unavailable`, `failed`, `cancelled`, `recovered_unknown`.
- **`InvocationAttempt`**: `attempt_id`, `lease_id`, `key`, `cycle_id`, `kind`, `outcome`, `reserved_at`, `started_at: datetime | None`, `finished_at: datetime | None`, `model_id: str | None`, `error: OperationalError | None`. `reserved` has no start/finish/model/error; `running` has start and selected model but no finish/error; terminal states have finish. `started_at >= reserved_at`; `finished_at >= started_at` when started, otherwise `finished_at >= reserved_at`. Allowed transitions are `reserved -> running|cancelled|failed|model_unavailable` and `running -> completed|failed|cancelled|model_unavailable`; recovery alone writes `recovered_unknown`. `model_unavailable` may occur before or after `start`, requires a selected model and an error whose category is `model_unavailable`, and never consumes automatic budget. `completed` requires a start and selected model and no error; `failed`/`recovered_unknown` require a categorized `worker_failed` error and never raw output, and `recovered_unknown` requires a prior start; `cancelled` requires no error and has no model only when cancelled before start. An attempt belongs to exactly one lease and is globally unique. Exactly one caller may win `reserved -> running`; that commit immediately before process creation is the sole durable launch authorization, and a crash after it is conservatively counted as an automatic launch.
- **`QueueItem`**: `repository`, `pr_number`, `author: str | None`, `head_repository: str | None`, `current_head_sha`, `observed_at`, `cycle_id`, `eligible`, `checks: CheckState`, `state`, `reason: RepairReason | None`, `remote_labels: tuple[WorkerLabel, ...]`, `automatic_attempt_count`, `manual_retry_count`, `last_error: OperationalError | None`, `updated_at`. Counts are non-negative exact integers; current SHA/cycle identify the open cycle. `automatic_attempt_count` is the current cycle's counted automatic launches across SHAs; `manual_retry_count` is the number of distinct manual retry authorizations issued in that cycle, unaffected by later expiry/consumption and reset only by a new cycle. Observed labels are unique and may temporarily include multiple distinct conflicts; a successful projection has at most one. `check_state` aliases `checks`; `updated_at >= observed_at` is the last durable local projection clock, distinct from remote `observed_at`. Eligibility/reason consistency is exact: ready has no reason and `eligible=False`; blocked has `eligible=False` and may retain a repair reason for capped/explicitly blocked work; queued/running always have a reason. Automatic queued work is eligible only with deterministic/Claude reason, capacity, and no blockers; paused or manual-awaiting-claim queued work is `eligible=False`. A successfully claimed manual attempt is running/eligible with `manual_retry` until terminal projection.
- **`QueueEvent`**: `event_id`, `repository`, `pr_number`, `head_sha`, `cycle_id`, `from_state: WorkerState`, `to_state: WorkerState`, `occurred_at`, `attempt_id: str | None`, `error: OperationalError | None`. It is an immutable transition/observation fact, never source/diff/feedback. A state change has differing states; an error-only observation may retain the same state. A final invocation event carries the attempt ID and the attempt's matching key/cycle.
- **`Eligibility`**: `eligible: bool`, `state: WorkerState`, `reason: RepairReason | None`, `blockers: tuple[ReadinessBlocker, ...]`. Classification handles automatic readiness: eligible requires queued/running, no blockers, and a deterministic-failure/Claude-feedback reason; the manual-claim overlay is the sole exception and may produce running `manual_retry`. ready has no reason and is not claimable; blocked is never eligible. Paused items remain queued with `eligible=False` and no invented blocker. A UI manual retry projects `manual_retry`; `claim` alone overlays valid authorization to make that item claimable. Host/CLI/model/broker blockers belong to source-plan Task 4, not this worker-disabled slice.
- **`RemoteRepositoryReport`**: `repository`, `health: RemoteHealth`, `failures: tuple[RemoteFailure, ...]`, `items: tuple[QueueItem, ...]`, `closed_pr_numbers: tuple[int, ...]`. **`RemoteHealth`** is `healthy`, `degraded`, `offline`, `stale`. **`RemoteOperation`** is `list_pull_requests`, `get_pull_request`, `get_checks`, `get_config`, `get_labels`, `set_label`. **`RemoteFailure`** is `repository`, `pr_number: int | None`, `operation: RemoteOperation`, `error: OperationalError`. Health precedence is stale for stale-head/remote-stale evidence, offline for transport/auth failures, degraded for other per-PR/config/label failures, healthy only when none fail. **`ReconcileResult`** is `reports: tuple[RemoteRepositoryReport, ...]` plus `items -> concatenated report items` and `remote_healthy -> every report healthy`; it is never collapsed to a bare item list on failure. Reports are sorted by repository, each report's items/closed PR numbers are unique and sorted numerically, and failures retain deterministic operation order.

### Existing UI Adapter Contract

Task 1 tests these adapters without importing PySide6 or changing UI files.
