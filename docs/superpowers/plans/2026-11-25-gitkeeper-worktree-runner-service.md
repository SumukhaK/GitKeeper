**Goal:** Add preserved per-PR/SHA/cycle worktrees, a real but fail-closed worker executor and fast-forward-only publisher, then compose the queue, reconciler, poller, runner, and existing companion UI protocols without enabling execution by default.

**Architecture:** The queue domain remains the authority for claims, attempts, retry authorizations, and fencing. Worker adapters consume a fenced claim, recheck authoritative facts, durably start exactly one invocation, and report one terminal outcome. Separate external stores hold worktree metadata and restricted feedback; Git publication uses a dedicated transport rather than expanding the label-only GitHub control plane.

**Tech Stack:** Python 3.10+, standard-library `sqlite3`, `subprocess`, `pathlib`, `dataclasses`, `threading`, and `pytest`; existing PySide6/QML optional dependency. No new runtime dependency.

**Spec:** [approved pilot design spec](../specs/2026-11-20-gitkeeper-setu-mobile-pilot-design.md)

**Prerequisite plan:** [queue persistence and reconciliation](2026-11-25-gitkeeper-queue-persistence-reconciliation.md). The full plan requires slices 1–7 merged; per-slice minimums are in the sub-slice tracker, and 3A–3D may start after slice 1.

## Global Constraints

- Worker execution remains disabled by default. `ApprovalBroker` continues to default to `execution_disabled`; production composition sets `execution_disabled=True`. No task may enable a worker, change settings/workflows, launch real OpenCode, or modify Setu-mobile.
- `ACCEPTED_HOST_MODE` is accepted risk, **not isolation or a sandbox**. A worktree, path check, prompt, allowlist, or approval dialog does not confine host commands. Keep the README/handover worker-disabled warning explicit.
- GitHub is authoritative for PR/head/check/config state. `QueueKey` has exactly `(repository, pr_number, head_sha)`; `cycle_id` is a separate fence. Together with exact lease ID, generation, and attempt ID they authorize a mutation. Owner, PR number, or SHA alone never does.
- A new head or PR close cancels exact stale work. Same-SHA close/reopen creates a fresh cycle and invalidates every old callback, retry authorization, process handle, and publication attempt.
- At most one worker process may be active across all repositories, enforced by the global queue lease and coordinator single-flight control rather than by holding a lock throughout execution. The shared lifecycle lock serializes only claim/cancellation fences, read-only publication reconciliation, final publication, and terminal projection; lock order is always per-PR projection lock (when needed), then shared lifecycle lock, then per-PR lock; publishers holding only lifecycle release it before projection. Close reconciliation holds the shared guard across its fresh `get_pull_request` read and close/reopen persistence, and the publisher holds it across its final fence, push, and read-back. Long worker execution must not hold this guard, so close/new-head reconciliation can cancel the exact active process and fence stale publication. Delayed pre-close observations are rejected by the persisted cycle `closed_at` tombstone. This is single-companion-process serialization, not a cross-service transaction or a distributed lock. The lock uses an interruptible timed acquire; pause/stop never abruptly kills an active process.
- At most three counted automatic launches per cycle across SHA changes. The unique `reserved -> running` commit immediately before process creation is counted conservatively, but the existing queue contract excludes any attempt whose terminal outcome is `model_unavailable`, including quota/rate limit detected after start; `reserved` consumes none and `recovered_unknown` from `running` adds no second count. Manual retry is one high-entropy, five-minute, single-use authorization consumed atomically with claim; it never resets the cycle budget.
- Only exact owner-selected `opencode/...` IDs may launch. The selected ID must equal `LocalModelPolicy.ladder.active` and be an exact member of both local and host-policy ladders. Never call `normalize_model_id` on launch input and never fall back to another model/provider.
- OpenCode CLI `1.19.6`, verified broker capability, passing host readiness, and `require_inert_worktree` are mandatory. Any missing/failed gate blocks before process creation.
- Preserve every worker worktree on unavailable CLI/model, quota/rate limit, crash, cancellation, stale head, scope failure, manual escalation, or unknown publication outcome. This plan ships no automatic deletion API.
- Publication is a normal fast-forward push to the existing PR head branch only. Never force, reset to remote, mix histories, push to the default branch, run Gradle locally, or intentionally inject control-plane credentials into OpenCode.
- Operational telemetry retains only the fixed queue schema for at most 90 days. Never persist source, diff, prompt, feedback, raw command/script, environment values, credentials, screenshots, or full OpenCode output.
- All state/worktree/cache roots are external to GitKeeper and every active watched checkout. Reject equality/descendance through resolved case-insensitive paths, symlinks, and junctions. Use absolute Windows paths; reject UNC, drive-relative, traversal, reserved-device, alternate-stream, and overlong paths.
- GitHub Actions is the sole Android test gate. Offline/partial remote failures preserve local records and never become false success.
- Every future implementation commit includes `Co-authored-by: Copilot App <223556219+Copilot@users.noreply.github.com>`. Each task requires its own PR, fresh review, merged evidence, and tracker update before the next task starts.
- **Atomic delivery:** every sub-slice below is its own PR: at most ~150 changed production lines and 3–4 files, one coherent behavior, no drive-by formatting, and a buildable/tested tree. Tests may exceed the production cap only when the PR description records the reviewer's approval. A slice that cannot fit is split further before coding; do not bundle "while here" fixes.

## Contract Rulings

1. **Budget/launch ownership:** Task 3 creates no invocation and consumes no budget. Task 4 alone rechecks gates and calls `QueueService.start(claim, job.model_id)` immediately before process creation. Task 5 does not move this responsibility.
2. **Worktree identity:** source-plan `WorktreeManager.create(...) -> Path` is superseded by `create(...) -> WorktreeRecord`. A record carries repository, PR, SHA, cycle, absolute path, and preservation state. Same-SHA reopen gets a new cycle-specific directory; old work is never overwritten.
3. **No discard shortcut:** source-plan `discard_or_preserve` is superseded by explicit `preserve(...) -> WorktreeRecord`. Cleanup requires a future owner-approved manual tool and is not part of Tasks 3–5.
4. **Patch scope:** the vague source-plan `RepairScope` is superseded by existing `PatchScopePolicy.evaluate(ScopeRequest) -> ScopeDecision`. The publisher must construct real `FileChange` values from Git. Current policy is Setu-mobile-specific; another allowlisted repository fails closed until its own policy is approved.
5. **Publication transport:** `GitHubControlPlane` remains read/label-only. A separate `PublishTargetPort` and `GitTransport` carry branch/fetch/commit/push responsibilities. Do not add `commit_and_push` to the GitHub protocol.
6. **Retry return:** retain the current queue-slice contract `QueueService.retry(pr_number) -> QueueItem | None` and the fake's compatible return. `QueueUIAdapter.retry` returns `QueueViewAdapter | None`; view models ignore the return and confirm refreshed state.
7. **Feedback:** preserve `submit_review_feedback(pr_number, head_sha, feedback)`. It requires a fresh authoritative open, owner-authored, same-repository, allowlisted, non-draft PR, exact current SHA, valid merged config, and passing current-SHA required checks. Passing PRs need not already be queued, and pause does not discard feedback; it queues work without permitting a claim. Reassociation occurs in the existing view model before submission; the service never silently rebinds stale text.
8. **Manual-retry readiness:** readiness's automatic `repair_reason` cannot represent `manual_retry`. Task 5 adds a persisted-cycle lookup for the last non-manual repair reason and passes that reason to readiness only after the one-shot retry has authorized the claim. Authorization never bypasses any other readiness gate. `QueueLaunchFacts.repair_reason` and the mapped `WorkerJob.repair_reason` are always that non-manual queue reason, never `manual_retry`; `QueueLaunchFacts.pull_request.repair_reason` carries the same value mapped through `to_readiness_reason`.
9. **Errors:** domain errors retain exact underscore values such as `remote_stale`, `stale_head`, `model_unavailable`, `worker_unavailable`, and `worker_failed`. UI adapters translate them to existing `QueueServiceError` categories; neither layer leaks raw exception text. Host-mode hyphenated blocker codes are mapped at the coordinator boundary, never exposed as queue error categories.
10. **Credentials:** no token location is invented. `GitTransport` is an injected control-plane adapter and accepts no credential fields. Production may use the host's existing Git credential helper only inside trusted clone/fetch/publish subprocesses; helper/configured values never enter argv, logs, results, or the OpenCode environment, redirects are disabled, and unit fakes perform no helper/network calls. An unapproved/missing push credential configuration fails closed and does not enable execution.
11. **Real broker executor:** `BrokerCommandExecutor` is the concrete `Callable[[CommandRequest], ExecutionResult]` that may be passed to the existing `ApprovalBroker`. Omitting it preserves `execution_disabled`; enabling it requires the explicit gate plus verified mediation. A high-level `WorkerExecutor` never bypasses broker approval.
12. **SHA width:** queue persistence accepts 40- or 64-hex SHAs, but existing `CommandRequest.starting_sha` requires lowercase 40-hex. Task 4 must block a 64-hex worker job as `worker_unavailable` rather than truncate, normalize, or invent a broker request. GitHub's current PR contract supplies 40-hex values.
13. **Runner worktree input:** source-plan `OpenCodeRunner.run(worktree: Path, ...)` is superseded by `WorkerJob.worktree: WorktreeRecord` and one `OpenCodeExecutor.execute(...)` that owns approval, bridge, and process lifecycle. Repository/PR/SHA/cycle authority cannot be detached from the process request.
14. **Pause:** pause prevents new claims at a safe checkpoint but never abruptly kills an active process. Cancellation is a separate exact, fenced request; late completion/publication remains forbidden after close/reopen or stale head.
15. **Broker shell handoff:** the production Node plugin calls a per-job loopback HTTP bridge. The companion reviews each exact script through `ApprovalBroker`; an approved `opencode-shell` request returns a fixed handoff result without spawning a second process. OpenCode itself runs its shell tool after the hook resolves. UI/audit wording must not claim that the companion spawned that tool. Top-level OpenCode denial/timeout/disconnect prevents queue `start`; plugin-shell denial happens after OpenCode started and blocks only that shell call.
16. **Primary-repository UI:** the binding pilot UI is PR-number-only and cannot disambiguate equal PR numbers across repositories. `CompanionServices.queue` therefore exposes only its declared `primary_repository`; reconciliation/coordinator maps may cover several repositories, but cross-repository UI selection requires a future explicit UI contract change.
17. **Late approval binding:** the existing UI creates `CommandApprovalViewModel` inside `main`. Coordinators receive a thread-safe `ApprovalPortBinding`; `main` binds that concrete view model before composed services start either background loop. Missing binding fails closed.
18. **Stale remote UI:** local SQLite reads can succeed while GitHub is offline. In addition to preserving the last snapshot on service exceptions, `QueueViewModel.refresh()` and `StatusViewModel.refresh()` mark it stale and disable queue controls/feedback submission when the composed remote-health adapter reports stale/offline/degraded after successful local reads.
19. **Approval-result correlation:** `ApprovalBroker` consumes approval before invoking its executor, so an executor exception can otherwise leave the UI at `queued-for-execution`. Extend `CommandApprovalViewModel.record_execution(result, request_digest=None)` compatibly; worker reporting always supplies `decision.request_digest`, and a mismatched digest cannot alter a newer approval. A fixed failure result is reported whenever an approved top-level request was consumed, including process-creation failure.
20. **Reserved refusals:** pre-start `worker_unavailable` is not a valid terminal `failed` attempt. Task 4 adds only the thin `QueueService.block_reserved(claim, error)` service adapter over the slice-5 store transaction `block_reserved(lease, now, error)`, which cancels the exact reserved attempt/lease atomically and then projects blocked with an error-only projection fact; do not add a second persistence path, re-declare the store method, or bypass the service clock; the attempt itself remains `cancelled` with no stored error and consumes no budget. Task 5 only consumes this merged method. Pre-start `model_unavailable` instead uses `complete(..., "model_unavailable", model_id=..., error=...)`.
21. **Scope anchor:** `PatchScopePolicy` remains unchanged and Setu-mobile-only. Its `ScopeRequest.head_sha` is the claimed PR-base anchor (`starting_sha`) for pre-commit, staged-index, and committed-tree evaluations; actual worktree HEAD is independently asserted by Git before and after commit. Passing the new commit SHA as the policy anchor would falsely trigger `HEAD_MISMATCH`. `active_checkouts` contains external checkouts only, excluding managed worktrees, or the existing policy would reject its own worktree.
22. **Prompt encoding:** feedback may contain newlines and Unicode, but `CommandRequest` rejects CR/LF/NUL argv entries. `build_worker_prompt` returns one physical line by appending lossless compact JSON (`ensure_ascii=True`, `separators=(",", ":")`); it never truncates. The Windows adapter rejects a projected CreateProcess command line or environment block over 32,767 UTF-16 code units before approval/start.
23. **Feedback durability:** Task 3 adds the restricted feedback store and a queue-neutral `FeedbackPort` in `queue/ports.py`; `QueueService` depends only on that port and never imports `gitkeeper.worker`. `FeedbackStore` in `worker/feedback.py` implements the port, and an import-direction test proves `import gitkeeper.queue.service` does not import `gitkeeper.worker`. Accepted feedback is persisted before projection; default reconciliation consults its exact unbound request, so restart does not lose a commit between feedback write and queue projection. Binding is permitted only for effective `claude_feedback`; manual retries may reuse the latest request in the same cycle.
24. **Unknown publication:** a preserved commit whose remote outcome is uncertain is never automatically relaunched or pushed. After scope validation and a fresh authoritative PR/head validation, the publisher commits, independently revalidates the committed tree, and—before the final push target read/dispatch—durably records an immutable `PublicationIntent` containing exact attempt/original key/cycle/worktree/starting-SHA/local-commit-SHA; this is a recovery marker, never push or launch authorization. An uncertain outcome then records an `UncertainPublication` association before terminal blocked projection. `QueueService.retry(pr_number)` selects a one-shot `reconcile_unknown` authorization, not a launch authorization. The coordinator selects that exact preserved worktree only by UUID4 and the reserved claim, creates an exact cancellation event/`is_current` callback but no process-registry entry, performs no process/running transition/push, and lets the publisher validate the exact registered worktree/commit/scope before a fresh target read. The claim may use the current observed key `C1` while the association retains original key `S0` only for the same repository/PR/cycle: validate the worktree record against original `S0`, require worktree HEAD and `association.local_commit_sha == C1`, and require fresh remote head `C1`. This makes a successful-but-unconfirmed `S0 -> C1` push reconcilable after polling advances the head. Publisher-validated equality calls `finish_reconciliation(claim, "remote_equal", None)`, finalizing the reserved attempt as `cancelled` without launch/budget; equality preserves an existing latch and creates none. Divergent head calls `remote_diverged`; refused worktree/scope/target validation calls `validation_failed`. Both use exactly `OperationalError(category=ErrorCategory.worker_failed, message="Preserved worker commit failed publication validation.", occurred_at=clock())`, finalize the reserved attempt as `failed`, set/preserve the latch, and project blocked. Transport-unknown reconciliation calls neither and preserves claim/association. If a crash after commit/push prevented association recording, startup/reconciliation scans `pending_publication_intents()` and, for each exact current-cycle intent under per-PR projection -> shared lifecycle -> per-PR locks, resolves the UUID4 worktree. Only exact registered identity with committed HEAD equal to `local_commit_sha` may be associated; missing/mismatched identity or any other HEAD instead durably sets/preserves the `worker_failed` latch and projects blocked while preserving the unresolved intent/attempt history. Any storage failure aborts launch selection for that pass. This intent-based path is reachable with execution disabled and passing/unknown/failing checks and does not require a claim, approval, readiness, config, model, broker, repair reason, or budget. It never starts anything and weakens no later launch gate. Startup runs this scan before generic expired-lease recovery can terminally mark the same attempt. An unassociated intent makes `retry` fail closed without consuming a token or granting launch; the owner may restore/repair the exact registered worktree at its preserved `local_commit_sha` out of band, after which the next scan associates it and explicit retry may issue only the read-only reconciliation token. Neither path counts a launch or clears the escalation latch; association sets/preserves it, including when the attempt was already cancelled by a same-cycle head change.
25. **Durable escalation:** failure, model unavailability, owner/runner cancellation, recovered unknown outcome, and pre-start `worker_unavailable` create a cycle-scoped manual-retry latch. Polling, changed heads, config changes, pause/resume, checks, reconciliation, and pre-start refusal cannot clear it. Only a valid manual launch authorization's durable `reserved -> running` transition clears it; close/reopen starts a fresh cycle without the old latch.
26. **Automatic repair-reason persistence:** automatic `RepairRequest` values have `owner=None`, `expires_at=None`, and no authorization, so the manual-only `retry_requests` table cannot store them. Slice 2 merged at `9318e45` without an `automatic_repair_requests` table, and its schema remains `user_version=1`. Task 5 must therefore add an explicit `user_version=2` migration that creates `automatic_repair_requests` (`request_id` PK, `repository`, `pr_number`, `head_sha`, `cycle_id` FK, `reason`, `requested_at`, unique exact `(repository, pr_number, head_sha, cycle_id, reason)`), bumps `_SCHEMA_VERSION`, extends preflight/verification, and migrates an existing version-1 database without resetting it. The worktree implementer verifies the migration exists in preflight; this is a Task 5 change, not a Task 3 step. Task 5's "no migration" wording is superseded; never edit the version-1 DDL or claim `user_version=1` is preserved while adding the table.
27. **Publish-target identity:** `PublishTarget` requires the exact PR head branch and a same-repository head. `PullRequestSnapshot.head_repository` exists, but `RemotePrState` does not carry it and `head_ref` is absent from every queue type. Task 4 adds `head_repository` to `RemotePrState`, rejects a fork or different head repository at publication, and resolves `branch` through a concrete `GitHubPublishTargetAdapter` (`worker/publish_target.py`) that reads `head.ref` from the authoritative PR response. Until that adapter is reviewed and merged, production composition omits the coordinator and publication remains a deployment blocker; tests use a fake.
28. **Windows mechanics:** `CreateProcessW(CREATE_SUSPENDED)` -> `AssignProcessToJobObject` (kill-on-close) -> `ResumeThread`, with fail-closed cleanup if any step fails; do not rely on `subprocess` to assign before execution. DACL helpers use the current user SID only (`SYSTEM`/`Administrators` only if the reviewer records why), set the DACL before writing the file, and re-verify it on open; `FeedbackStore` and broker token files share `worker/win_acl.py`. Output capture continuously drains both pipes, retains at most 65,536 combined bytes, and discards the rest so the child cannot block on a full pipe. Git subprocesses run with `GIT_CONFIG_NOSYSTEM=1`, a controlled `GIT_CONFIG_GLOBAL`, `GIT_TERMINAL_PROMPT=0`, and explicit `-c` overrides for `core.hooksPath`, `url.*.insteadOf`, filters, and `safe.directory`; host config must not redirect or execute code. Push/fetch use a bounded timeout; a timeout records `GitPushOutcomeUnknown` and the uncertain association before releasing the shared guard.
29. **Staging and commit:** the worker edits the working tree; `PatchPublisher` stages exactly the validated paths (or `git add -A` inside the managed worktree after a fresh dirty/untracked inspection), re-inspects the staged index, commits once with controlled hooks disabled, re-inspects the committed tree, and only then records the publication intent. `GitTransport` gains `stage(path, paths) -> None`; the publisher calls `worktrees.assert_active_checkouts_unchanged()` immediately before commit and again before push. `remote_head` uses `git ls-remote` with a timeout, never a cached remote-tracking ref.
30. **Prerequisite consumption:** Task 3 replaces only the slice-5 fail-closed `submit_review_feedback` body and verifies the slice-6 `cancel_reconciled_lease` wiring; it does not re-declare either method, duplicate their tests, or re-implement reconciler routing. Task 4 adds only the service `block_reserved` adapter. Any signature mismatch discovered during preflight stops the task and updates the queue plan first.
